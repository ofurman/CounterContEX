# Plan: Outcome-Based (Verification-Only) Counterfactual Training

## Context

Current CounterContEX trains on ground-truth counterfactual deltas generated by perturbing SCM inputs. This creates problems: (1) multi-modal targets (many valid CFs per input), (2) perturbation strategy bias (model mimics the strategy, not causal structure), (3) low flip rates requiring filtering/retry.

**New approach**: Don't generate ground-truth counterfactuals at all. Generate only observational `(x, y)` data from SCMs, let the model predict deltas, and verify via differentiable SCM forward pass whether the prediction actually flips the label. Train with `L = BCE(SCM_classify(x + Δ), y_target) + λ₁‖Δ‖₂ + λ₂‖Δ‖₁`.

This eliminates all three problems and aligns with how TabPFN trains (cross-entropy against actual labels, not matching GT posteriors).

## Execution Protocol

For each stage: implement → run verification → update progress tracker → commit.
One commit per stage. Do not skip ahead.

**Device**: Use MPS (`mps` device on macOS) for training and evaluation throughout all stages.

## Stage 1: Observational-Only Data Loaders

**Goal**: New data loader that generates only `(x, y)` from SCMs — no perturbations, no counterfactual pairs.

**Files**: `tabpfn/priors/counterfactual_prior.py`

**Steps**:

1. Add `get_batch_observational()` function:
   - Instantiate `CounterfactualSCMGenerator`, call `gen.generate_batch()` but only use `x_factual` and `y_factual_class`

   - For query positions: flip labels (`y_target = 1 - y_factual`)
   - Return `(x, y, target_y_zeros, scm_data_list)` — target_y is zeros (unused by outcome loss)

3. Add `FixedSCMOutcomeDataLoader` class — mirrors `FixedSCMDataLoader` but uses observational batch (no perturbations)

**Reuse**: `CounterfactualSCMGenerator._sample_scm()`, `_normalize_per_batch()`, `_normalize_with_cached_stats()`

## Stage 2: Outcome Loss Function

**Goal**: Standalone `_outcome_loss` using only verification-based signals.

**Files**: `tabpfn/train_counterfactual.py`

**Steps**:

1. Add `_outcome_loss(output, query_x, target_labels, scm_data_list, num_features, single_eval_pos, proximity_weight=0.1, sparsity_weight=0.01, temperature=1.0)`:
   - Extract `pred_delta = output[..., :num_features]`
   - Per batch element: un-normalize `x + delta` to raw space, call `scm.differentiable_forward()`, compute `BCE(temperature * (y_cf - threshold), target)`
   - Add `proximity_weight * ‖delta‖₂ + sparsity_weight * ‖delta‖₁`
   - Return scalar loss

   Pattern: Nearly identical to existing `_validity_loss` (lines 287-381) but standalone with temperature parameter.

2. Add curriculum schedule helper `_outcome_schedule(epoch, total_epochs)`:
   - `temperature = min(1.0, 0.1 + 0.9 * epoch / (0.2 * total_epochs))` — soft early, sharp later
   - `proximity_weight = max(0.1, 1.0 - 0.9 * epoch / (0.2 * total_epochs))` — high early, low later

**Verification**:
- Unit test: `_outcome_loss` returns scalar with gradients flowing to model parameters
- Verify loss decreases when delta is constructed to actually flip the label

**Commit**: `feat(train): add outcome-based loss with curriculum scheduling`
