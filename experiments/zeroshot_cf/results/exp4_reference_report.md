# Exp-4 beam-search counterfactuals — scored with the reference (dicoflex) metrics

Generated by `experiments/zeroshot_cf/reference_metrics.py` from the saved arrays in
`results/arrays/`. Raw output: `results/exp4_reference_metrics.json`.

## Where the metric code comes from

Verbatim ports of **`cel/metrics/dicoflex_metrics.py`**, commit `b9715ef`
("feat: add dicoflex-aligned metrics for CETGFN comparison", Oleksii Furman,
2026-04-26) on branch `origin/ofurman/CFN_baselines` of the `counterfactuals` repo.
That module is not in the working tree — it was read out of git history.

It is selected by `cel/pipelines/conf/metrics/dicoflex.yaml`, which lists exactly the
paper's Table-1 columns:

```
validity, proximity_l1_continuous, sparsity_categorical, eps_sparsity,
lof_score_median_log, pairwise_diversity_mixed, number_of_instances
```

Its docstring states the formulas mirror `rgfn/trainer/metrics/counterfactual_metrics.py`
from the CETGFN project, so results are directly comparable to the DiCoFlex authors'
own evaluation. `GOAL_table1_metric_config.md` in that repo identifies this module as
authoritative and documents that three of five formulas differ from the generic `cel`
registry:

| metric | reference (used here) | generic cel registry |
|---|---|---|
| `eps_sparsity` | relative: `abs(dx) / (abs(x) + 1e-8) > 0.05` | absolute: `abs(dx) > 0.05 * range` |
| `sparsity_categorical` | mean over one-hot **columns** | mean over one-hot **groups** |
| `pairwise_diversity_mixed` | euclidean (cont) + `hamming * len(cat)` on raw one-hot | cityblock + hamming on argmax-collapsed codes |
| `proximity_l1_continuous` | `mean(abs(dx))` over continuous | same |
| `lof_score_median_log` | `median(log(-score_samples + 1e-8))`, LOF fit on `X_train` | same |

All metrics except validity are computed on **valid counterfactuals only**, where valid
means `y_cf_pred == y_target` (`counterfactuals/metrics/orchestrator.py:96`). The
reference also aggregates as a single pooled mean/median over all valid CFs, not as an
average of per-factual values.

## Protocol difference — read before comparing to published numbers

The reference pipelines target the flip of the **true** label
(`y_target = np.abs(1 - y_test_origin)`, e.g. `run_cchvae_traintest_pipeline.py:125`).

This project **relabels**: the target is the flip of the discriminator's own prediction
on the factual (`exp4_beam_search.py:144-145`):

```python
y_pred = disc_model.predict(X_test)
y_target = 1 - y_pred
```

In the reference setting the two coincide, so cel's registry `validity`
(`mean(y_cf_pred != y_test)`, `basic_metrics.py:65`) is well defined there. Under
relabelling it reduces algebraically to the discriminator's test accuracy and says
nothing about the generator — verified exactly:

| dataset | disc. accuracy | `validity_vs_true` |
|---|---|---|
| heloc | 0.7232 | 0.7232 |
| law | 0.7815 | 0.7815 |

**Use `validity_target` = `mean(y_cf_pred == y_target)`.** Both are emitted so the
mismatch stays visible.

## Caveats — three numbers that must not be reported as published values

### 1. `sparsity_categorical` = 1.000 on Law is an artifact

The formula uses exact float inequality and assumes the method emits discrete one-hots
(DiCE, CCHVAE and DiCoFlex all do). Beam search emits a continuous relaxation:
**0.0%** of Law's CF categorical cells are exactly 0 or 1 — values look like
`[0.999, 0.001, 0., ...]`. Every column therefore registers as changed and the metric
saturates at 1.0 regardless of content. Some rows carry two columns near 1 within the
same group, so the output is not on the one-hot simplex at all.

Diagnostic replacement (argmax-decode each group, then compare):
`sparsity_categorical_decoded` = **0.2354**. This is not what the reference computes and
belongs in a separate column.

### 2. `pairwise_diversity_mixed` is N/A, not 0

The metric measures spread across the K counterfactuals a method proposes for one
factual; the reference runner supplies `cf_group_ids` from `result.extras`. Beam search
emits exactly one CF per factual, so there is nothing to measure.

Run verbatim it does not return a clean zero either — it groups by the *value* of the
factual row, and HELOC's test split contains one block of 115 byte-identical rows
(2092 rows, 1978 unique). Generation is deterministic, so those 115 yield identical CFs
and the group contributes pairwise distance exactly 0, which would read as perfect
diversity. The implementation here refuses the number.

### 3. `eps_sparsity` is inflated by construction

The relative denominator `abs(x) + 1e-8` on MinMax-scaled data means a feature sitting
at x ≈ 0 makes any change count as significant. The 0.46–0.92 range partly reflects that,
not just generation behaviour. Kept as-is because it is the reference definition.

## Finding: the LOF 6.5e6 result was an artifact

Earlier scoring reported HELOC frozen at mean LOF **6.53e6** against Law's 8.72 — a
~750,000× gap treated as the project's main open question. Under the reference metric
HELOC frozen is **0.0345** against from-scratch's **-0.0136**. The gap does not exist.

Two compounding causes, both confirmed against the arrays:

**Valid-only subsetting.** On the 787 valid CFs, mean LOF is 1.06 and max is 1.70. The
6.53e6 came from including the 1305 invalid CFs, whose mean is 1.05e7.

**A degenerate duplicated row.** Exactly 115 rows have LOF > 1e3 (max 1.19e8), and they
are byte-identical to the 115-row duplicate block — HELOC's **all-zeros row**, the
MinMax image of the `-9` "no record" code. `X_train` contains 473 copies of it. A query
point sitting on a 473-fold duplicated training point has k-NN distance ≈ 0, so local
reachability density diverges and the LOF ratio explodes numerically.

Freezing the 6 immutables pins those rows to that degenerate point; from-scratch lets
them move away. That is the whole reason the two regimes looked so different on LOF.

Median + log aggregation, which is what the reference uses, is immune to the tail.

| aggregation over HELOC frozen | value |
|---|---|
| mean, all 2092 CFs (previously reported) | 6.53e6 |
| mean, 787 valid CFs | 1.06 |
| median-log, 787 valid CFs (reference) | 0.0345 |

**What survives:** frozen-regime validity of **0.376** against 1.000 from-scratch is a
genuine result, unaffected by any of this. The plausibility collapse is not.

**Open data-quality issue:** the 115 all-zeros rows are a missing-data code, not real
records. They affect every metric computed on HELOC, not only LOF, and it is worth
deciding whether they belong in the evaluation set at all.
